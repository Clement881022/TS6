# 戰鬥介面提案 04

日期：2026-10-10。手機橫式優先，手牌最多 10 張，依使用者最新指定取代早期 12／16 張推估。這是可點選的視覺與觸控原型，未接入 Unity 戰鬥結算；3D 場景是 Blender 離線渲染，並非用生成圖片替代人物模型。

## 本輪變更

- 手牌隨張數增加而靠攏重疊：800×450 下，3／7／10 張的間距分別為 120／約88／約59 單位；1000×450 的10張間距約81。全部容納，不使用分頁或橫向捲動。
- 每張只顯示費用、名稱、持有人、右上角大類型。類型包括傷害、治療、增益、減益、護盾；移動牌暫示「移動」，正式資料分類交由企劃確認。
- 由左側卡片覆蓋下一張左部，保留每張右上角類型與右側資訊區；密集時名稱可換行，弓兵／盾兵採可辨識短稱。點選後完整展開，右側呈現完整持有人與效果，重點牌提高並描邊；再點收回。沒有將選牌直接視為出牌。
- 手牌高96、底部操作區116，主要詳情字級16；名稱14、費用16、類型與持有人12。這些小標仍需實機閱讀驗收，沒有宣稱文字尺寸已達商業上線品質。
- 左側隊伍名冊移除。七名人物名稱、HP條、HP數值與護送標記皆在頭上HUD。HUD由相機投影座標定位，正式版必須每幀追蹤頭部錨點。
- 戰場採草地、裸土與碎石混合材質；無棋盤格與拼接邊框。邏輯格不因此刪除。選目標或移動時才顯示合法位置提示，移動與命中規則保持原設定。
- 右側暫以任務提示填補未選牌狀態，選牌後換成詳情，位置穩定。頂部常駐選單收納低頻操作，沒有直接勝利等測試按鈕。

沿用人物：`client/Assets/Resources/ProductionCharacters/` 的 liubei、r_shield、r_archer、r_villager、bandit_archer、bandit_grunt、bandit_shaman 七組 prefab、原網格、材質與貼圖。`scene.py` 讀取 Unity YAML 網格資料、骨骼權重、bind pose 與 prefab 變換，烘焙成靜態 Blender 展示場景。沒有修改這些原始資產，也沒有宣稱新增人物模型；這次只展示靜態姿勢，尚未驗證動畫一致性。

新增 `assets/ground-grass-dirt.png`：內建 imagegen 生成的自然地表 albedo，原輸出 `exec-a7921c58-2268-4cef-b85a-484b2474cd68.png`，保留原像素。提示詞見 [image-prompts.md](image-prompts.md)。`assets/battlefield.blend` 保存3D场景，`battlefield-1600.png` 與 `battlefield-2000.png` 為兩種比例的直接渲染；`anchors.json` 保存HUD投影座標。字體與道具小圖沿用 ChibiSkin／Fonts。

## Claude Code 接入範圍

Codex可處理地表素材、HUD外觀與手牌顯示版面。程式端需接原有卡牌實例ID、費用、名稱、持有人及企劃指定的大類型；詳細數值從戰鬥資料提供，不能把本稿的鼓舞／破甲示範文字新增成遊戲規則。選牌→右側詳情→既有合法目標／確認流程，出牌取消與滑動判定依原規格接入。手牌上限10張是使用者提供的既有需求。

HUD使用角色頭部錨點，不用本稿的靜態百分比；血量、護盾、狀態與陣營讀取實際資料。地面換材質但保留原位置判定，僅在需要操作時顯示格位。正式安全区讀取裝置回報，底部背景延伸至邊緣、操作保留內距。尚未完成Unity接入、硬體閱讀與連續戰鬥驗收。

以 Blender 執行 `scene.py` 重建兩種比例渲染；開啟既有本機預覽服務後用含 Playwright 的 Node 執行 `render.cjs` 輸出觸控紀錄與畫面。未發布。
