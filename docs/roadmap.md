# 開發範圍與里程碑

> 狀態：草案。數字與順序為建議，待你確認時程。

## 1. MVP 目標

1. **戰鬥好不好玩**：核心卡牌棋盤戰鬥的手感與策略深度。
2. **第 1–7 天進度**：玩家前 7 天能玩到的內容與成長節奏。

MVP 不含：競技場（後面再做）、營運活動（限購、通行證等）、完整 3D 美術。

## 2. Demo 內容量（已同意）

- 4–6 名武將（簡易 3D 佔位模型，共用骨架與動畫）
- 1 個章節、約 10 個關卡
- 完整牌庫戰鬥（共用費用與手牌、移動按鈕、敵方意圖、自動 / 手動）

## 3. 技術

- 客戶端：Unity（C#）。
- 伺服器：.NET + Aspire（與你現有後端同系統）。
- 抽卡、存檔、付費驗證必須在伺服器端（防作弊，也是合規需要）。
- 建議把**戰鬥模擬核心**寫成與 Unity 無關的 C# 類別庫，客戶端與伺服器共用：
  - 同一套規則可在伺服器驗證戰鬥結果（防作弊、競技場防守隊結算）。
  - 可在 Unity 外用單元測試做數值平衡。
  - 資料（卡牌、武將、機率）以資料表驅動。

## 4. 里程碑（建議）

| 階段 | 內容 | 驗證重點 |
|---|---|---|
| M0 | 戰鬥模擬核心（純 C#）＋數值試算工具 | 規則自洽、可自動對戰 |
| M1 | Unity 戰鬥原型：佔位模型、手牌 UI、意圖顯示 | **好不好玩** |
| M2 | 養成與關卡：等級、突破、卡牌強化、10 關、體力 | 第 1–7 天進度 |
| M3 | 後端：帳號、存檔、抽卡、體力（.NET + Aspire） | 資料在伺服器 |
| M4 | 商業化最小集合：元寶、月卡、成長基金（測試環境） | 付費流程跑通 |
| M5 | 美術替換、音效、新手流程、合規整備 | 可對外測試 |

## 4.1 M0 進度（2026-10-06）

已完成（`src/SanGuo.Core`，netstandard2.1，22 個單元測試全數通過）：
- 棋盤與單位、同路最前排 / 最後排目標判定、5 種範圍形狀、無目標不可打出
- 全隊共用費用（每回合 +3、上限 10）、牌庫循環（洗回重抽）、破釜 / 蓄勢 / 先登
- 6 種狀態中的護甲、火攻、瘟毒、昏亂、破甲、挑釁（持續回合與結算時機已實作）
- 乘法減傷公式、爆擊 / 閃避、自研可重播亂數（跨平台一致）
- 敵方簡單 AI（打得到就攻擊、否則移動；挑釁強制追擊）與意圖預覽 `GetIntent`
- 自動戰鬥（由左至右能出就出）與 Demo 內容（劉備、關羽、張飛、諸葛亮、趙雲 vs 黃巾）

未完成 / 已知缺口：
- 復活、擊退 / 拉扯 / 換位技能效果；敵方蓄力、召喚、增益等意圖
- 資料目前以 C# 程式碼定義，尚未接 ScriptableObject → JSON 匯出
- 資料尚未改成 ScriptableObject → JSON 匯出（M1 先沿用程式碼定義的 Demo 內容）

**數值調整紀錄**：
- 第一版：自動對戰 200 場全勝，平均 29.9 回合（目標 30–60 秒約 6–10 回合）。掃描參數後發現回合數幾乎只由我方輸出決定（每回合約 100 點，太低），不是敵人太硬或太弱。
- 調整：我方攻擊 ×1.5、我方血量 ×0.8、敵人血量 ×0.5、敵人攻擊 ×2。結果：平均 8.6 回合，勝率約 100%（作為教學關合理）。
- 待辦：做一組「難關」敵人，目標勝率約 40–70%，並以自動對戰驗證；自動戰鬥「能出就出」是下限，手動操作應明顯更好。

**開發環境**：Unity 6.3 LTS（6000.3.25f1），已安裝（含 Android 支援），專案在 `client/`。

## 4.2 M1 進度：Unity 戰鬥原型（2026-10-06）

已完成：
- `client/` Unity 專案；戰鬥核心以 DLL 引用（`tools/sync-core.ps1` 建置並複製到 `Assets/Plugins/SanGuo`）。
- 戰鬥畫面（UI Toolkit，全程式碼建立，樣式在 `Assets/Resources/UI/Battle.uss`）：棋盤、血條與護甲 / 狀態、敵方意圖、手牌、費用、牌堆數量、戰鬥紀錄、自動戰鬥、重來、勝敗畫面。
- 手牌互動：滑過手牌預覽會打到哪些目標（黃框）；按下「移動」按鈕後先標出可移動的武將，選定後顯示可移動格（綠框）；無目標 / 費用不足會提示。
- 驗證流程：`tools/shot.ps1` 一鍵打包 Windows 版並自動操作截圖到 `build/shots`，不需要人工開 Unity 就能檢查畫面。

注意 / 待辦：
- 原型借用 Windows 系統中文字型，手機上沒有，之後必須內嵌 CJK 字型（見 Android 打包）。
- 手機觸控、動畫與演出、音效尚未做；目前沒有武將 3D 模型，用文字方塊佔位。
- 場景由 Editor 選單「三國 / 建立戰鬥場景」產生，不需手動拖拉。
- **橫式為主**：參考解析度 1920x1080，棋盤左右相對（5 路由上到下），Game 視窗用任何比例都會等比縮放。
- `tools/shot.ps1` 會把專案複製到 `build/client-copy` 再打包，因此你開著 Unity 編輯器時也能跑（同一專案不能被兩個 Unity 同時開）。

## 4.3 美術原型管線（2026-10-06）

- 已安裝 **Blender 5.2.1 LTS**（winget），可用命令列腳本建模與渲染：
  `blender -b --python tools/blender/chibi.py -- build/previews`
- `tools/blender/chibi.py`：以參數表程式化生成 Q 版武將（身體 / 大頭 / 髮型帽飾 / 鬍子 / 肩甲 / 武器），目前有劉備、關羽、張飛、諸葛亮、趙雲與黃巾兵，輸出預覽圖 `build/previews/heroes_preview.png`。新增武將只要加一筆參數。
- 定位：**佔位美術**，足夠驗證戰鬥與演出；商業上線前仍需替換為正式角色模型、立繪與卡面。
- 尚未做：骨架綁定與動畫、匯出到 Unity（FBX / glTF）、圖示（icon）。
- 戰鬥演出（`BattleFx`）：傷害 / 治療 / 護甲 / 狀態 / 閃避 / 倒下的飄字、出手前衝、受擊抖動；自動戰鬥會等演出播完再出下一步。核心事件現在帶有發生當下的位置，單位死亡後仍可定位特效。

## 4.4 3D 戰場與角色（2026-10-07）

- **等角視角**：戰場是 3D 的，正交攝影機俯視 50°、左右轉 45°（`BattleStage.CameraPitchDegrees` / `CameraYawDegrees`），地磚呈菱形；攝影機自動把棋盤框進畫面中間區域。雙方沿對角線相對，5 路排列，前排靠近中線。我方在近鏡頭側，因此多半看到我方背面 / 側面。
- **UI 配置**：右下角 = 手牌 + 費用 / 移動 / 結束回合；左下角 = 戰鬥紀錄；上方 = 回合與自動 / 重來。
- 角色是 Blender 腳本生成的 Q 版 FBX（`client/Assets/Resources/Characters/`），含頭、手臂、軀幹樞紐；`CharacterView` 用程式動畫驅動：待機呼吸 / 攻擊（蓄力→前衝→揮臂）/ 施法（跳起舉手）/ 受擊（閃白 + 後仰 + 抖動）/ 倒下（後倒縮小）。
- UI 只負責手牌、費用、紀錄與角色頭上的小標籤（名字、血條、護甲 / 狀態、敵方意圖）；技能目標預覽（黃）、移動可選武將與可到達格（綠）、已選武將（白）都改成地磚上色；移動時直接點地磚。
- 重新產生模型：`blender -b --python tools/blender/chibi.py -- export client/Assets/Resources/Characters`。
- 已知問題 / 待辦：
  - 5 路縱向很擠，斜視下標籤會蓋到後面那一路的角色；之後可改為只在懸停 / 選取時顯示完整資訊，或調整地磚間距。
  - 動畫是程式動畫，不是骨架動畫；前衝 / 揮臂 / 受擊等動態只在靜態截圖驗證過站位與朝向，手感需要實際試玩。
  - 弓、手持小物件較小；角色是低多邊形佔位，不是商業品質。
  - 移動後角色會平滑滑到新格，沒有腳步動畫。

## 4.6 M2 進度：玩家存檔與體力（2026-10-07）

## 5. 風險

- 範圍：3D 武將、卡牌戰鬥、三條養成線、抽卡、後端，對單人是很大負擔 → 每階段都要能獨立驗證，不通過就不往下走。
- 美術是最大不確定性（3D 與動畫量）。
- 大陸上線的版號與發行門檻（見 README 合規）。
