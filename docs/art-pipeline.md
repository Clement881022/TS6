# 美術製作管線與規格

> 狀態：草案。目標是讓 Demo 的美術**一律是占位**，日後專業美術交件時可以直接替換，不需要改程式。

## 1. 美術方向（來自使用者參考圖）

兩張參考圖共同的特徵（僅作為風格方向，**不得複製既有遊戲的角色設計**）：

| 項目 | 描述 |
|---|---|
| 比例 | Q 版，**頭身比約 3 頭身（使用者指定）**，頭大、眼睛大、身體小但保有四肢與服裝細節 |
| 線條 | 粗而深的描邊，輪廓清楚 |
| 色彩 | 高飽和、高對比；主色大塊配金色飾邊 |
| 質感 | 金屬鎧甲有強烈高光、漸層與光澤；披風、髮絲有動態感 |
| 構圖 | 動態姿勢、斜角構圖，背景為暖色調的古風城鎮 / 燈籠 / 火光 |
| 特效 | 刀光為青藍 + 紅色拖尾，星芒閃光 |
| 表現形式 | **戰鬥**：3D 卡通渲染角色（描邊 + 階梯明暗）；**立繪 / 卡面**：2D 手繪 Q 版插畫 |

## 2. 資產分類與占位策略

| 類別 | 用途 | Demo 占位方式 | 正式交件 |
|---|---|---|---|
| 立繪 / 卡面（Portrait） | 抽卡、武將資訊、卡牌插圖 | 本機 AI 生成的占位圖 | 專業美術手繪（分層 PSD） |
| 戰鬥 3D 角色 | 戰場上的模型與動畫 | Blender 程式化生成 + 卡通著色 | 專業 3D 美術（FBX + 共用骨架） |
| 場景地面 / 裝飾 | 戰場環境 | 純色地磚 | 專業場景美術 |
| 特效 | 刀光、受擊、治療 | 程式 / 粒子占位 | 特效美術 |
| UI 圖示 | 牌型、狀態、職業 | 程式 / AI 占位 | UI 美術 |

**所有 Demo 美術一律視為「占位、不可上線」**，必須在資產清冊登記。

## 3. 資產清冊（Provenance Manifest）

檔案：`art/manifest.json`。每個美術資產一筆，欄位：

| 欄位 | 說明 |
|---|---|
| `id` | 資產識別（例：`portrait.guanyu`） |
| `file` | 專案內相對路徑 |
| `kind` | `portrait` / `model3d` / `icon` / `texture` / `vfx` / `ui` |
| `status` | `placeholder`（占位，不可上線）或 `final`（正式，已驗收） |
| `shippable` | 是否可隨正式版發行（占位一律 `false`） |
| `source` | `ai-local` / `procedural` / `artist` / `stock` |
| `tool` / `model` | 使用的工具與模型名稱、版本 |
| `model_license` | 模型 / 工具授權（含商用限制） |
| `prompt` / `seed` | 生成參數（AI 資產必填，作為人類創作與修改過程的紀錄） |
| `created` | 建立日期 |
| `replace_by` | 預計由誰 / 何時替換 |
| `notes` | 備註 |

上線前檢查：任何 `shippable: false` 的資產出現在發行版 → 建置失敗（日後在打包腳本加入檢查）。

## 4. 為什麼要這樣做

- 完全由 AI 生成、缺乏人類創作控制的內容，版權可能不受保護；大陸另有 AIGC 標識要求。清冊讓我們知道**哪些是 AI 生成的**，上線前可以全部換掉或補上人工創作紀錄。
- 角色美術換人時，程式碼只依賴「資產 id → 檔案」的對應，不依賴具體圖片內容。

## 5. 交件規格（給專業美術，草案）

### 5.1 立繪 / 卡面
- 格式：分層 PSD（保留髮、臉、身、武器、披風、特效等圖層），另附去背 PNG。
- 尺寸：2048 × 2048 以上，透明背景；角色置中，保留武器與披風的空間。
- 一名武將至少 2 張：全身立繪、卡面（含背景構圖，可裁成直式卡牌比例）。

### 5.2 戰鬥 3D 角色
- 格式：FBX（Y-up，單位公尺，正面朝向 -Z），貼圖 PNG。
- 骨架：全員共用同一套骨架（Humanoid 風格），以便動畫共用。
- 動畫清單：Idle、Attack（近戰 / 遠程各一）、Cast、Hit、Die、Victory。
- 面數：角色 8k 三角形以內；材質 ≤ 3；貼圖 ≤ 2048²。
- 命名：`<heroId>_<part>`，heroId 與資料表一致（如 `guanyu`）。

### 5.3 檢查清單（驗收）
- [ ] 風格符合美術方向文件，且為原創設計（非既有遊戲角色的複製）。
- [ ] 檔案命名、尺寸、面數符合規格。
- [ ] 已在 `art/manifest.json` 登記，`status: final`、`shippable: true`，來源與授權明確。

## 6. 待決

- 戰鬥 3D 角色是否改為共用骨架的人形（目前 Demo 為多部件樞紐的程式動畫）。
- 場景美術風格（古風城鎮 / 戰場）與地磚材質。
- UI 皮膚風格與字型授權（目前借用系統中文字型，手機沒有，必須內嵌）。

## 7. 立繪來源決策（更新）

- 曾以本機 AI（ComfyUI + SDXL / Animagine XL）試做占位立繪，使用者評估**效果不符期待**，已停止並**全部移除**（環境、模型、生成腳本、圖片與清冊紀錄皆已清除）。
- 之後的立繪占位改用**使用者任職公司提供的素材**；引入時仍須在 `art/manifest.json` 登記來源、授權與「占位 / 不可上線」狀態。
- 比例規格維持：約 3 頭身（見第 1 節）。卡牌讀取 `Resources/HeroArt/<DefId>.png`，目前資料夾為空，卡牌顯示文字版面。
