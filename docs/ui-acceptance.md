# UI 展示版驗收

**此報告屬於已撤回的舊寫實／象牙面板版本。使用者指出它與選定的 Q 版示意圖不符；原「可提交」判定失效。現行重製規格與驗收記錄見 `ui-chibi.md`。**

本輪以投資人展示的可操作 Demo 為目標，評估真實遊戲畫面與操作流程。UI 驗收不等於整款遊戲完成上線驗收。

## 判準

- 第一眼能辨識遊戲題材、主線入口與資源，避免背景、邊框、文字同時搶焦點。
- 字型固定字重，主要文字與背景對比清楚；長名稱與數字完整可讀。
- 招募、養成、編隊、戰鬥使用一致的青綠、象牙、銅金語彙；場景保留自然亮度。
- 小解析度下主要操作不裁切；列表可捲至最後一項。
- 可完整展示招募十連、養成分頁、隊伍配置、選牌、目標預覽、出牌、結算及回主城後的數值更新。

| 可變中文字型預設字重為 100 | 從原字型生成固定 500 字重供 UI 使用，保留原始字型 |
| 主城進度條樣式沒生效 | 共用樣式名稱分詞處理；驗證戰後經驗與主線進度 |

| 商店分頁寬度坍縮 | 獨立商店分頁布局，將魂清單使用固定版心與捲動 |
| 五階副本首尾被裁切 | 五階卡片同屏排列，調整卡寬、獎勵與字級 |
| 空白 Unity 主題缺少 ScrollView 內部樣式 | 明確定義捲動內容、視窗、軌道與滑塊，驗證最後一位武將 |

| 長名稱被截斷或壓住等級 | 名牌換行，稀有度、等級與名字分區；驗證長名稱武將 |
| 十連結果尚未播完便截圖 | 等待最後一張動畫完成，驗證完整兩排十張 |
| 資源不足的招募／兌換仍顯示可操作 | 停用對應操作並顯示費用提示 |

| 字重調整後血量換行，敵方標籤相互覆蓋 | 血量單行、標籤尺寸重排、敵方資訊避讓與詳情面板預留 |
| 大型白色棋盤與整體美術不一致 | 青石色棋盤、較細銅色格線，保留目標與移動高亮 |
| 5:4 螢幕縮放壓窄武將展示區，卡片換行後裁切 | 改為 Expand 參考畫布縮放，方正螢幕保留參考寬度並增加垂直空間 |
| 方正螢幕戰場沿用寬螢幕放大比例，棋盤邊緣出界 | 依螢幕比例調整初始鏡頭放大率，保留手動縮放能力 |

## 驗證方式與證據

`tools/verify-strategy-ui.ps1` 同步核心、在隔離副本打包，再跑真實遊戲中的頁面與戰鬥操作路徑。每次必須新產生 23 張截圖，檢查 runtime log，避免舊截圖造成假通過。

證據在 `build/ui-review/<解析度>/`：`capture-manifest.json`、`player.log` 與逐頁 PNG。建置結果在 `build/strategy-build.log`，可操作版本為 `build/strategy-win/SanGuo.exe`。

截圖流程包含：主城、招募、十連結果、地圖、關卡詳情、武將三分頁、武將列表末端、長名稱武將、五階副本、任務與七日獎勵、兩個商店分頁、編隊、戰鬥起始／懸停／選取／出牌／勝利，以及戰後主城。操作由遊戲內驗證程序呼叫真實頁面與戰鬥邏輯；尚未將人工滑鼠逐項點擊驗收記為通過。

## 本次提交判定（2026-10-08）

UI 視覺與自動操作流程驗收通過，可提交為投資人展示的可操作 Demo。最終同一份 Windows 建置在 1920×1080、1366×768、1280×1024 各產生 23 張新截圖，共 69 張；截圖尺寸檢查通過，三次執行記錄中的 runtime error 均為 0。核心與 Unity Windows 建置成功，程式差異空白檢查通過。

逐輪人工目視檢查主城、招募結果、關卡面板、武將長名稱與名冊末端、副本、任務、商店、編隊、選牌、出牌與結算截圖；最後修正方正螢幕的畫布與鏡頭縮放。畫面統一為自然場景光、青綠頂欄、象牙資訊面板與銅金主要操作。

## 製作範圍

本輪重做 UI 與 2D 美術。現有 3D 武將仍為原專案模型，部分武將依職業共用模型，與新立繪的精細程度不同。商店仍使用測試付款流程。這兩點不以 UI 驗收冒充已完成製作。
